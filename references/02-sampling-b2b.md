# B｜访谁：样本角色、近似样本与 B2B 采购/实施事件

## 一张小而清晰的画像选择卡

每次只给与研究目标相关的 **2–4 类**候选，不要从“越有钱的人越好”出发。每类写：`能提供的事实` / `最低筛选条件` / `可能偏差` / `本轮优先级`。

### To C：按经历分，而不只按人口属性

| 画像示例 | 能回答 | 最低筛选条件 | 可能偏差 |
|---|---|---|---|
| 最近亲历困境、尝试解决的人 | 真实触发、步骤、替代办法、后果 | 在 `[可回忆时间范围]` 内有一次具体事件，能说出采取过什么行动 | 可能放大刚发生时的情绪 |
| 已用其他方式解决的人 | 替代方案、切换成本、权衡与实际投入 | 确实完成过一次相关任务或选择 | 幸存者偏差；不代表无解者 |
| 遇到问题但没行动/放弃的人 | “不做”背后的限制和重要性 | 能叙述一次选择搁置的真实情境 | 可能事后合理化 |
| 相邻旅程阶段的人 | 触发前的准备、后续影响 | 与目标场景有可说明的相邻经历 | 不可代替目标阶段的亲历细节 |

筛选尽可能核实实际事件而非态度。可问：“最近一次你处理 `[中性描述的任务]` 大概是什么时候？”“当时你具体做了哪一步？” 避免“你是否也深受 X 困扰？”

## To B：把组织采购中心还原成事件，不是组织架构图

### 八类需要**考虑**的角色（非默认都存在）

| 事件中的作用 | 关键要了解的实际动作 |
|---|---|
| 实际使用者 | 如何完成任务/绕路；真正用到了什么 |
| 需求发起者 | 谁在哪个情境首次提出改变；出发点是什么 |
| 专业影响/评估者 | 谁制定标准、试用比较、提供意见或反对 |
| 决策者 | 谁在**该事件中**作出选择/有效否决，何时如何体现 |
| 预算批准者 | 谁批准/否决金额或资源，按什么实际程序 |
| 采购/签约者 | 谁询价、选供应商、走合同、合规或采购流程 |
| 实施落地者 | 谁部署、培训、管理变更、协调推广 |
| 信息把关/阻碍者 | 谁掌握必要信息/系统入口/安全意见，哪里被卡住 |

一人可兼任多角色，一个作用可由多人共同承担；项目大小、决策类型和组织差异都可让角色变动。没有证据时，不把“CFO=预算批准者”“律师=审批人”这样的职位映射写成事实。

### 围绕“最近一次真实事件”重建过程

先确定**具体事件**：采购、未采购、试用、评估、升级续签、被否决、内部自建、上线失败均可。按顺序问：

1. “你最近**实际参与或了解得比较清楚**的一次 `[采购/评估/实施]` 是什么？大概什么时候？”
2. “最初是谁在哪个场合提起要解决这个问题的？你是亲历、看见消息，还是后来听说？”
3. “往下一步，谁去找了什么信息？谁定义评估指标？你本人具体做了哪一步？”
4. “谁在何时拍板，预算是谁批准的，合同谁处理，谁安排落地？这些事实你怎么知道的？”
5. “在什么步骤卡住、搁置或改变方向？有没有人明确不同意？最后有没有真的启动/付款/使用？”
6. “如果当时没有走采购，大家实际怎么完成这项工作？”

制作 `assets/08-b2b-event-map.md`：每条事件-角色记录必须加证据标签 `SR/OBS/DOC/HO/HYP` 与来源。受访者不了解时写“未知；需问某角色”，不要请其猜整个组织。

### 什么时候需要补访另一角色？

- 受访者是使用者，但关键未知是预算逻辑、实际供应商选择 → 优先找本次参与审批/采购的人。
- 受访者是决策者，但你想知道重复性日常工作、绕路办法 → 优先找实际执行/使用者，并可申请经同意的流程走查。
- 受访者只听说一项项目 → 在需要下判断前补访事件亲历者/查看获准的材料。
- 可能存在组织政治、保密或者签约流程 → 尽可能分开访谈，避免把小组讨论当可靠的个人亲历证据。

### 近似样本矩阵

| 约不到 | 可以先访 | **能回答** | **不能替代** |
|---|---|---|---|
| 大企业 CIO 预算批准者 | 同类采购的项目负责人/财务协同者 | 决策流程线索、可能的关键节点、该人亲历的协调 | CIO 实际批准逻辑与权力事实 |
| 目标客户中真正付过费的自由职业者 | 最近认真对比过方案但未购买者 | 阻碍行动、替代办法、评价/放弃过程 | 真实付款后的效果与付费动机 |
| 一线使用者 | 该流程的运营/培训/支持人员 | 观察到的流程和常见卡点（注明来源） | 最终使用者的亲身步骤与感受 |

**近似不等于等效**：每个结论关联样本“适用范围/不能外推”。可先用近似样本磨炼题目，但一旦研究决策依赖不可替代的权力或经验，就明确记为未解决的研究缺口。

### Knowing Whom 触发条件

询问“你愿意用以前的人际网络盘点一起找线索吗？”对方明确说**愿意**后才使用历史记忆/网络盘点；不能以“过去大概认识很多人”为由直接搜索。如果没法查到，说明缺口，可让用户自行列出三个关系来源（前同事、相关社群、校友等）；只建议**关系类型**，不虚构名单、不主动联络、不要求别人交出未同意的联系人。

### To C + To B

把“谁用、谁付、谁决定、谁受影响”分别画出来。先问学员本轮决定是偏体验可行性还是组织采纳可行性；对两类人各立一张研究卡，共享主题但证据分开分析。
