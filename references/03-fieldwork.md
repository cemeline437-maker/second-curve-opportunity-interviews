# C｜招募、访谈、试访与小组引导

## 研究计划不是逐题审讯

推荐提纲结构：
1. **开场说明/知情同意**：研究正在了解现有做法，不评价人、不推销方案；可跳过问题/随时退出；确认资料如何使用和匿名化程度。**单独询问能否录音及其后续用于 AI 转写/分析的范围；不同意不录，照常访谈**。
2. 容易回答的背景：只有助于理解目标经历的背景，不为了“画像完整”问隐私。
3. 用最近一次**具体事件**起步：什么时候、怎么发生、为何想起这件事。
4. **先开放**跟随时间线：“你当时是怎么一步一步完成的？”→先后动作、角色、结果；**再**依据对方实际说到的工具、渠道、手段追问具体如何使用。只有受访者自行提及、或确有明确待核查依据时，才中性追问 Excel、群聊、AI、系统等具体工具。不要预填工具链、痛点、原因或预期解决方案。
5. 检视影响：投入的时间、钱、风险、注意力、情绪成本（情绪要问实际经历，不假设“焦虑”）及“没采取行动”的成本。
6. 真实交易与资源：问实际支付、已有预算、签约记录、投入/放弃动作、替代投入，**不等于问愿付多少钱**。
7. 决策链与不同意见：B2B 用事件角色映射；C 端仅在相关时问谁一起商量/影响。
8. 反例与遗漏：“有过更顺利/根本没遇到问题的情况吗？”“哪些环节我还没问到但重要？”

每个核心问题交付**五列**：`原句` / `研究意图` / `可选追问` / `误导或偏差的问法（反面例子）` / `较中性的替代问法`。完整示例见 `assets/03-interview-guide.md`。根据卡片做定制，不允许直接照搬行业细节。提纲核心题数量应贴合 `[时长]`，不要强迫逐题问完；用 ★ 必问 / ○ 机动标注。**对新手的正式交付是完整定制文档**（`assets/09-complete-research-plan.md`），分“任务卡／访前招募／访谈现场／访后复盘”四区，聊天中只发摘要和已验证的全文入口。不要以较短的现场导航取代完整文件。

### 常用自然追问

- “能不能从那天一开始讲起？”
- “然后发生了什么？你当时具体做了什么？”
- “当时你实际怎么完成的？”（先让对方自由说；提到工具后才追用途和切换）
- “你记得大约哪天、花了多久、找了哪些东西吗？”
- “那一步是谁做的？你自己参与了哪部分？”
- “你刚才说‘很麻烦’，能不能讲一个最具体的时刻？”
- “你后来怎么知道结果的？”
- “这次有没有什么地方和上次不一样？”
- “有哪种情况根本没发生这个问题？”
- “‘你会不会买’我先不问。你之前遇到类似需求，实际花过钱、时间或找过别的解决办法吗？”

### 当受访者给出观点、猜测或未来意愿

可记录为 AT/HYP，但先追问：“你想到的是哪一次已经发生过的事？” 若无相关事件，不强迫，诚实标记 `无具体事例/假设性判断`，后续换有经历的人。不要问“为什么不……”责备当事人；也别为了要“正面反馈”反复逼问。

### To B 的信息来源核查

“你是自己参加了这次会议，看到邮件/系统通知，还是同事后来和你说的？”“谁比较清楚那一步？”“这个结论是你亲眼看到的，还是你的判断？” 如无亲历者可暂记录 `HO/HYP`，不写“公司确定由 X 决策”。避免询问机密、索取内部敏感文件。受访者可自愿概括或提供已经授权的材料。

### 现场记录轻量化

独立访谈者别把注意力都放在逐字记录。使用 `assets/04-field-notes.md` 的关键词/时间戳：一句原话（若确信逐字）、一个动作、一个令人意外的细节、一个待追问。大量内容只有同意录音才交给后期转写。没有录音时用简短记录，访谈后立即补“自己的摘要”；**摘要不是逐字引语**。研究者看到当场迟疑/停顿可标 `OBS:访谈中的表现`，但不能据此证明访谈主题中的日常行为。

### 可选：只做一个回合的追问演练（不是正式交付门槛）

当学员表示“我怕现场不会追问/记不住”时，征求是否愿意用一回合练习：
1. 教练扮演受访者只说一句空泛回答，例如：“系统反正不好用，老板也不管。”
2. 让**学员自己**问一个下一句；不要先替学员写满分答案。
3. 只反馈最重要的一处，例如“你追问到哪一次了没有？”或“是否不小心假设了原因？”然后给一个更中性的示范：“你想到最近哪一次？当时发生了什么？”
4. 学员不练就跳过，不因此卡住已确认目标后的**完整计划交付**。

### 第一场试访复盘（立即进行）

- 受访者有没有讲出一段**可排序的真实事件**？哪道题听上去像“对产品的态度调查”？
- 哪个词不自然、带预设，或让人只回答“是/否”？
- 记录/录音权限是否清晰？是否偏离研究问题？
- 是否遗漏某种关键人/角色/未行动者？
- 明确记录下一步分支，而不是默认“再找第二个人”：
  - **无可核对具体事件** → 补问一件最近发生的事；仍无则调整筛选，找真正亲历者。
  - **事件清楚，但关键环节未知** → 向本人补问或找对应角色；B2B 不由受访者猜预算/采购行为。
  - **现有办法已够用/流程很顺** → 保存为反例，比较适用情境，不贴“没需求”标签。
  - **出现另一个新场景** → 先确认是否仍服务同一决定；否则另建研究任务卡，避免混合。
  - **有麻烦却未付费/未行动** → 追当时实际取舍；一次抱怨不等于可商业化，没行动也不等于无需求。
- 在 `assets/07-change-log.md` 填旧题、改动理由、新题、日期/适用范围，以及上述**首访后判断**；**不能悄悄改变任务卡的研究目标**。若目标本身确需改变，明确创建 v2 研究卡并解释新旧结果不可直接合并。

## 小组访谈分支（仅学员选择多人时）

**用途与局限**：可探索多人如何讨论、共享语言、不同经验和社会规范；不适合把大家当作独立样本统计，群体认同会改变个人表达，机密/权力敏感的采购过程宜补一对一。

主持流程：
1. 说明保密边界（主持人无法保证其他参与者不转述）、允许退出、同意记录/录音规则，对多人都需要适用同意。
2. 避免一开始群体脑暴。让**每人先单独写下/回想**最近一件相关经历，轮流说各自行为和结果，标记说话人代号。
3. 主持人邀请不常发言者补充，防止专家或高职位者垄断；允许不同意见而不逼迫共识。
4. 后半段讨论不同经历的差异和互相影响：哪件事是亲历、谁接过话、在哪些地方受别人提醒才想起。
5. 对未展开的关键事件/决策链和敏感议题，安排后续一对一或事件回访，不能把群体附和当独立证据。

招募小组也用真实的研究名义；明确多人一起谈，不误称一对一。


## 招募落空与时间约束

计划中把“主动投入的联系/筛选时间”和“等待回复的日历时间”分开，二者都可能未知。例：`主动约人 [待确认]；等待回信 [取决于对方]`，不把“10 分钟发消息”称为“10 分钟约到人”。

若首位拒绝或没人回复，先检查邀请对象是否真正具有目标事件、文案是否说明了研究目的、是否存在时间/渠道障碍，再考虑另一条**同一事件相关**的关系路径或近似样本。不要为了尽快完成而随便找一个毫无相关经历的熟人；无法约到合格事件者时保留研究缺口，不捏造样本。
